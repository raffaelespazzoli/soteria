## Successes

1. **Real storage infrastructure fully operational.** Two Minikube KVM2 clusters with Cilium Cluster Mesh, Rook-Ceph with RBD mirroring, KubeVirt nested virtualization, ScyllaDB cross-DC on XFS — all working together. The platform that was theoretically designed for 13 epics now has the physical infrastructure to validate against.

2. **Build-up pattern applied to infrastructure.** Stories followed a clean dependency chain: clusters (14.1) → storage (14.2) → compute (14.3) → validation (14.4) → database (14.5) → orchestrator (14.8). Each story had a functioning, verifiable deliverable before the next began.

3. **`setup-all.sh` orchestrator script delivers reproducible environments.** Calls `setup-clusters.sh`, `setup-rook-ceph.sh`, `setup-kubevirt.sh`, `validate-fedora-vm.sh`, `setup-scylladb.sh` in sequence with fail-fast, `--skip` support, and teardown in reverse order. Any developer can bring up or tear down the full multi-site environment from scratch.

4. **Correct decision to move Stories 14.6 and 14.7.** Soteria deployment depends on Epic 15 Go code changes (resync guard, ShadowPV, reprotect simplification). Deploying before those changes would mean redeploying. The E2E test must validate all Epic 15 logic — running it before the code exists is pointless.

5. **Cilium Cluster Mesh replaced Submariner successfully.** The original Epic 14 plan used Submariner for cross-cluster networking. Cilium's `service.cilium.io/global` annotation on Services proved simpler and more reliable, with no gateway overhead.

## Challenges

1. **All-infrastructure epic is atypical for this project.** Previous epics (1–13) were predominantly Go code with well-established review and testing patterns. Shell scripts, Kustomize overlays, and YAML manifests don't have the same testing infrastructure. Review rigor was inconsistent because the tooling is different.

2. **Verification steps defaulted to warn-and-continue.** Smoke tests in scripts would log warnings but continue when verification failed. For infrastructure that downstream stories depend on, failure should stop the pipeline. This was identified as a process gap and captured as an action item.

3. **Prerequisite checks incomplete in some scripts.** Tools like `jq`, `bc`, `kustomize` were used without preflight checks. If a tool is missing, the script fails mid-execution with a cryptic error instead of failing immediately with an actionable message.

4. **Sprint-status integrity gap.** Story 14.6 was initially marked "done" in sprint-status.yaml despite having no dev agent record or completion notes. The discrepancy was caught during this retrospective. Status updates should require evidence.

---

## Key Insights

1. **"Infrastructure epics require different review rigor."** Go code has linters, unit tests, and conformance suites. Shell scripts have none of that by default. Future infrastructure stories should specify explicit verification steps in acceptance criteria — not just "the script runs successfully" but "the script's smoke test fails on X."

2. **"Fail-hard is the safer default for infrastructure."** In application code, graceful degradation is often correct. In infrastructure provisioning, fail-hard is almost always correct. A half-provisioned Rook-Ceph cluster is worse than a failed provisioning step with a clear error. The team adopted fail-hard as the default for all verification/smoke test steps going forward.

3. **"The environment is the product for this epic."** Unlike code-centric epics where the deliverable is a Go package, Epic 14's deliverable is a reproducible, working multi-site Kubernetes environment. The quality bar is: can someone else run `setup-all.sh` and get a working environment? That's the test.

4. **"Moving stories is better than rushing them."** Stories 14.6 and 14.7 could have been force-completed in the current sprint with the existing code. Moving them to Epic 15 ensures they validate the complete Epic 15 codebase — which is the whole point of an E2E test.
