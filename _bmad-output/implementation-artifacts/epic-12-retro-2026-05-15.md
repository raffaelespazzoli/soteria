## Successes

1. **100% story completion, zero spawned stories.** All 8 stories delivered cleanly through the `bmad-dev-story` workflow. The build-up pattern (struct refactor → types → skeleton → client → CRUD → state transitions → health → conformance) created a predictable, low-ambiguity implementation path.

2. **Build-up pattern produced zero-debug driver implementation.** Stories 12.1 through 12.6 had zero debug issues. Once the types and client were in place, the CSI extension driver methods implemented cleanly. Only Story 12.0 had debug issues (3, all trivial).

3. **Conformance suite validated the driver contract immediately.** All 27 conformance subtests pass via the `conformanceAdapter`, proving contract compliance. The adapter bridged 3 deviations cleanly (PVCNames injection, NonReplicated simulation, status reconciliation).

4. **UAT found real, impactful integration-seam bugs.** All 5 bugs were integration-seam issues — not driver logic bugs. Every driver method worked correctly in isolation. The failures were in the orchestration layer (PVC resolution, RBAC, label threading, cache semantics, update conflicts). This validates that unit tests catch logic errors and UAT catches integration gaps.

5. **Root cause analysis spawned a well-designed follow-up epic.** UAT-12.004/005 weren't just patched — they were traced to a fundamental lifecycle inversion (VR CRs as execution-level artifacts vs. plan-level infrastructure). Epic 13 with 7 architectural decisions and 10 stories was designed in-session.

6. **90.1% driver package coverage.** Comprehensive tests: unit tests, conformance suite (27 subtests), integration lifecycle tests, health mapping tables, error injection via interceptor.Funcs, and concurrent access with `-race`.

---

## Challenges

1. **5 UAT bugs is a project high-water mark.** Previous epics found 0-2 UAT bugs. Five (3 blockers) indicates systemic gaps in pre-UAT validation for cross-cutting integration concerns. All 5 were in integration seams, not driver logic.

2. **Three blockers in the orchestration wiring.** UAT-12.001 (DataVolume support), UAT-12.002 (RBAC verbs), UAT-12.003 (label threading) — none were in the driver code itself. All were in the orchestration layer that connects the driver to the reconciler/executor. Unit tests for the driver don't exercise this wiring.

3. **Stories 12.0a and 12.0 violated the 10-AC cap.** Story 12.0a had 15 ACs and 12.0 had 16 ACs. Both were large fixture-sweep or controller+validation stories. While both completed without spawning stories, the AC count exceeded the team agreement from Epic 9.

4. **Story 12.3 had the most review patches (5).** This was the first story touching real Kubernetes CRD management (create/delete/get with labels, namespace scoping, idempotency). Seven additional items were deferred.

5. **UAT-12.004 exposed an informer cache fundamental.** Using `mgr.GetClient()` for Create→List in the same goroutine is a known Kubernetes antipattern. Fixed tactically with `NewWithReader` + `mgr.GetAPIReader()`. Epic 13 will revert this.

6. **UAT-12.005 exposed a concurrency design gap.** The noop controller reconciles VR CRs concurrently with StopReplication/SetSource. `retry.RetryOnConflict` fixes the symptom but the root cause is that VR CRs shouldn't be created during execution.

---

## Key Insights

1. **"Unit tests validate logic; UAT validates wiring."** All 5 UAT bugs were integration-seam issues. The driver's 90.1% unit coverage caught zero of these. Every new external resource type needs an integration validation checklist (RBAC verbs, label threading, cache behavior, concurrent controller races).

2. **"The second implementation exposes the first implementation's assumptions."** The noop driver has no side effects — no Kubernetes resources, no RBAC, no informer cache, no controller races. Every one of these assumptions was invisible until the csi-extension driver broke them.

3. **"Root cause analysis during UAT is high-value work."** The tactical fixes for UAT-12.004/005 took minutes. The architectural analysis that spawned Epic 13 took serious thought but produced 7 architectural decisions and a well-structured 10-story epic.

4. **"Stories that create Kubernetes CRDs need more review scrutiny."** Stories 12.3 and 12.4 had 5 and 3 review patches — the highest in the epic. CRD management stories should be flagged for extra review attention.

5. **"Fixture sweep stories can exceed the AC cap without harm."** Stories 12.0a (15 ACs) and 12.0 (16 ACs) exceeded the 10-AC limit but were fundamentally mechanical. The 10-AC cap is appropriate for logic-heavy stories; fixture sweeps may exceed with justification.

## Significant Discovery — Epic 13 Spawned

UAT-12.004 and UAT-12.005 exposed a fundamental lifecycle inversion: VR/VGR CRs are created as execution-level artifacts when they should be plan-level infrastructure.

**Architectural Decisions (Party Mode Session):**

| Decision | Summary |
|----------|---------|
| AD-1 | DRPlan owns VR/VGR lifecycle — creates during plan setup, not during execution |
| AD-2 | Both sites create and monitor their own VR/VGR CRs (active=primary, passive=secondary) |
| AD-3 | Dual finalizers `soteria.io/vr-cleanup-{siteName}` for cascade cleanup |
| AD-4 | Per-site ReplicationHealth status fields (mirrors SiteDiscovery pattern) |
| AD-5 | CSI driver reverts to cached client once VR CRs are pre-created |
| AD-6 | Event-driven reconciliation replaces 30s passive polling |
| AD-7 | DRPlan owns DRExecutions via ownerReference |

**Tactical fixes remain until Epic 13:**
- `NewWithReader` + `mgr.GetAPIReader()` (reverted in Story 13.7)
- `retry.RetryOnConflict` for VR CR updates (kept — noop controller still races)
