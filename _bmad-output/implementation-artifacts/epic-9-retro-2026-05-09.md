## Successes

1. **100% completion, zero splits, cleanest epic in project history.** Five of seven stories had zero debug issues. Review patches dropped to ~1.6 per story (down from ~3.8 in Epic 8). AC counts averaged 6.1 — well within the 10-cap.

2. **Short stories are easier to get right.** The tight scoping (5–7 ACs) combined with sequential dependency chains meant each story had a narrow, well-defined input contract. No ambiguity about what data was available. This was explicitly called out by Raffa as the key success factor.

3. **Sequential build-up pattern eliminated rework.** 9.1 (disk enrichment) → 9.3 (cross-site comparison) → 9.4 (preflight VG enrichment) → 9.5 (SC homogeneity) → 9.6 (Console display) → 9.7 (cross-site PVC mapping). Each story consumed the previous one's data cleanly.

4. **Story 9.2 (admission plugin migration) fixed a latent correctness issue.** DRExecution and DRPlan ValidatingWebhookConfiguration entries never fired for aggregated API resources. Migration to in-process admission plugin resolved this with direct REST storage reads — no stale cache, no network hop. The adopted approach (direct composition) was simpler than the spec'd plugin registry pattern.

5. **UAT-8.001 and UAT-8.002 resolved.** Live investigation during this retro confirmed: UAT-8.001 (SitesInSync race) is already fixed in the codebase via in-memory SiteDiscovery population before agreement checks. UAT-8.002 (RequeueAfter broken) was a misdiagnosis — root cause was UAT-8.001; the requeue mechanism works correctly (10m normal, 30s degraded health). `GenerationChangedPredicate` on the `For()` watch is correct behavior preventing infinite reconcile loops.

6. **Story 9.7 (spawned from UAT) was cleanly identified and delivered.** UAT-9.001 identified that single-site VG disk view was a visibility gap. Story 9.7 restructured from flat `PVCName`/`PVCNamespace` to per-disk `DiskSiteMapping` with cross-site entries.

## Challenges

1. **UAT-9.001 — single-site VG disk view not caught in planning.** Story 9.4's design only showed the active site's PVC mapping. Cross-site comparison requires both sites' data. This spawned Story 9.7. Low impact (clean spawning, not a rework), but highlights that cross-site data visibility should be a standard review checkpoint.

2. **Manual Console UAT continues to be deferred (4 consecutive epics).** Scripted Console plugin UAT smoke test was committed in Epic 7 retro and has not been implemented. Risk is mitigated by 592 tests with jest-axe, but manual verification remains a gap.

3. **Carried-over infrastructure items accumulate.** UAT-8.004 (deploy script), OLM bundle validation, and envtest expansion continue to carry forward. None are blocking, but the list grows.

## Key Insights

1. **"Short stories are easier to get right."** The 10-AC cap combined with tight scoping (5–7 ACs per story, ~6.1 average) eliminates most implementation friction. Zero-debug stories become the norm, not the exception.

2. **"Two-bug interactions are more dangerous than either alone."** UAT-8.001 (one-cycle stale read) + 10-minute normal requeue interval looked like "requeue is broken." Live code investigation was more effective than a formal spike — resolved in minutes what was open for an entire epic.

3. **"Build-up patterns create natural dependency chains that reduce ambiguity."** Type → validation → enrichment → UI is a repeatable pattern. Each story has a clear input contract from the previous one.

4. **"In-process admission is architecturally superior to webhooks for aggregated API resources."** The VWC entries for soteria.io resources were dead code — webhooks don't fire for aggregated API. Direct REST storage reads in the admission plugin provide fresh state without stale-cache races.

5. **"Review patches follow a predictable taxonomy."** The ~11 patches across 7 stories break down into: backward compatibility (legacy string[] handling, deprecated field fallbacks), edge cases (stateless VMs, nil SiteDiscovery), and platform integration (VG chunk scoping, admission error messages). This taxonomy is stable and could inform story spec checklists.
